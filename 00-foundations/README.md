# 00-foundations — ジャンル横断の前提

> 各ジャンル（`data-modeling/` / `persistence/` / `ui-rendering/` 等）に入る前に必要な「**言語そのもの・道具そのもの**」を扱うレイヤ。

---

## なぜ別レイヤか

`~/dev/learning/` 直下のジャンル（data-modeling / persistence / state-and-time …）は **概念の塊** を扱う。「何を表現するか」「どう保存するか」のような **言語非依存** の問い。

しかし実際にコードを書くには、その概念を載せる **言語の構文**・**道具の使い方** が要る。それを別ジャンルにすると概念学習が脱線するので、ここに分離する。

「ジャンル横断で何度も顔を出すが、ジャンルそのものではない」もの:

- プログラミング言語の構文（`javascript/`、将来 `typescript/`、`java/` 等）
- ターミナル・シェル（将来 `terminal/`）
- バージョン管理（将来 `git/`）
- 型システム基礎（将来 `type-systems/`）

## 運用原則

- **必要になったら作る**: 全部最初に揃えない。ジャンル学習で詰まった時点で foundations 側に書き起こす
- **応用ジャンルからリンクで参照**: 例えば `ui-rendering/` の React 教材は `00-foundations/javascript/` の該当節へリンクする（重複説明を避ける）
- **Dreyfus 段階を意識**: 各 foundation は「Lv.2 を超えるまで」を主眼にする。Lv.3 以上は応用ジャンルで実戦的に育てる
